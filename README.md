# 📦 Sing-Box Extended Installer

Интерактивный установщик и обновлятор [sing-box-extended](https://github.com/shtorm-7/sing-box-extended) для OpenWrt и совместимых Linux-систем.

Установщик автоматически определяет OpenWrt, пакетный менеджер, архитектуру, наличие Podkop, состояние сервиса, доступную RAM и свободное место во flash-памяти, после чего выбирает подходящий сценарий установки.

## ✨ Возможности

- 🔄 **Интерактивный выбор версии** — получает стабильные релизы с GitHub и предлагает 3 последних доступных версии.
- 🧩 **Автоопределение окружения** — показывает версию OpenWrt, наличие Podkop, пакетный менеджер, состояние сервиса, архитектуру, RAM и flash-память.
- 📦 **Поддержка `opkg` и `apk`** — автоматически выбирает IPK/APK или замену бинарного файла в зависимости от окружения.
- 🛡 **Совместимость с Podkop на `opkg`** — сохраняет штатный пакет `sing-box` в базе `opkg`, а `sing-box-extended` устанавливает заменой `/usr/bin/sing-box`.
- 🔧 **Исправление package state на `opkg`** — если ранее вместо штатного `sing-box` был зарегистрирован `sing-box-extended`, установщик заранее скачивает штатный IPK и восстанавливает корректное состояние пакетов перед заменой бинарника.
- 📱 **Нативная установка APK** — на OpenWrt с `apk` можно установить обычный `sing-box-extended.apk` с полной интеграцией в пакетный менеджер.
- 🗜 **APK + Compressed (UPX)** — после установки APK можно дополнительно заменить `/usr/bin/sing-box` на compressed-версию, сохранив пакетную интеграцию и уменьшив расход flash-памяти.
- ⚙️ **Normal / Compressed** — при бинарной установке пользователь сам выбирает обычную или UPX-сжатую сборку.
- 🧠 **Защита от OOM** — при выборе Compressed установщик анализирует RAM и предупреждает о риске OOM на малопамятных устройствах.
- 💾 **Контроль временного места** — учитывает `/tmp`, свободную RAM и flash; большие файлы не держатся во временном хранилище дольше необходимого.
- 🚚 **Последовательная установка APK + Compressed** — сначала устанавливается и удаляется временный APK, затем отдельно скачивается compressed-архив, чтобы не хранить оба файла одновременно в `/tmp`.
- 🏗 **Мультиархитектура** — ARM, x86, MIPS, RISC-V, s390x и другие поддерживаемые upstream архитектуры.
- 🚫 **Compressed отключён для MIPS** — для MIPS-сборок автоматически используется Normal.
- 🔐 **Без встроенного GitHub-токена** — личный токен запрашивается только при rate limit/ошибке авторизации GitHub API.
- 🌐 **Безопасная работа с TLS** — отключение проверки сертификата предлагается только после неудачного HTTPS-соединения и требует подтверждения пользователя; GitHub-токен через такое соединение не отправляется.
- 🩺 **Проверка запуска** — после обновления установщик ждёт запуска `sing-box` и проверяет, что процесс стабилизировался, а не завершился сразу после старта.
- 🪶 **Без backup/rollback** — установщик не создаёт копии большого бинарника и не расходует дополнительную RAM/flash на автоматический rollback.

## 🔀 Режимы установки

### OpenWrt + Podkop + `opkg`

Типичный сценарий для OpenWrt 24.10 и систем с `opkg`.

Podkop ожидает штатный пакет `sing-box`, поэтому `sing-box-extended.ipk` не устанавливается вместо него. Установщик сохраняет системную интеграцию штатного пакета и заменяет только бинарный файл:

```text
штатный пакет sing-box в opkg
            +
/usr/bin/sing-box → sing-box-extended
```

Пользователю предлагается:

```text
1) Normal
2) Compressed (UPX)
```

Если штатный `sing-box` отсутствует в базе `opkg`, установщик сначала исправит состояние пакетов и только затем заменит бинарник.

### OpenWrt + `apk`

Типичный сценарий для OpenWrt 25.12 и новее, где используется `apk`.

Доступны два режима:

```text
1) APK-пакет
   Обычная пакетная установка sing-box-extended.apk.

2) APK + Compressed (UPX)
   Устанавливается sing-box-extended.apk, после чего
   /usr/bin/sing-box заменяется compressed-бинарником
   из того же релиза.
```

Обычный APK — рекомендуемый вариант.

`APK + Compressed` предназначен для устройств, где важна экономия flash-памяти. UPX может увеличивать пиковую нагрузку на RAM при запуске, поэтому на устройствах с небольшим объёмом памяти установщик показывает отдельное предупреждение.

> [!IMPORTANT]
> После `apk upgrade` или `apk fix` пакетный менеджер может восстановить обычный `/usr/bin/sing-box` из APK. Если нужен Compressed, достаточно повторно запустить установщик и выбрать `APK + Compressed (UPX)`.

### OpenWrt + `opkg` без Podkop

Если Podkop не обнаружен и доступен подходящий IPK, используется обычная установка IPK-пакета.

### Другие Linux-системы

Если OpenWrt/package manager не обнаружены, установщик работает в режиме замены бинарного файла и предлагает Normal или Compressed.

## 🧠 Normal и Compressed

### Normal

Рекомендуемый вариант для большинства роутеров.

- без UPX;
- более предсказуемое потребление памяти;
- меньше риск OOM при запуске;
- занимает больше места во flash.

### Compressed (UPX)

Используется для экономии flash-памяти.

- бинарник занимает меньше места;
- при запуске требуется дополнительная RAM для распаковки;
- на слабых роутерах может сработать OOM-killer;
- при недостатке памяти установщик предупреждает пользователя и предлагает вернуться на Normal.

Compressed автоматически не используется для MIPS.

## 🛡 Особенности работы с Podkop

Podkop создаёт часть служебных ruleset-файлов во временном каталоге `/tmp` во время запуска. Поэтому после остановки Podkop установщик не выполняет ложную проверку конфигурации по отсутствующим временным ruleset-файлам.

Вместо этого новый бинарник проверяется на запуск и определение версии, а полноценную конфигурацию Podkop формирует и использует уже при собственном старте.

Состояние Podkop определяется по реальному процессу `sing-box`, а не только по результату `/etc/init.d/podkop running`.

После запуска установщик ждёт стабилизации `sing-box` до 60 секунд, что позволяет Podkop выполнить необходимые перезапуски во время инициализации.

## 💾 Работа с памятью и временными файлами

Установщик показывает доступные ресурсы ещё до скачивания:

```text
Оперативная память: 235 МБ всего · ~96 МБ доступно
Flash-память: 72 МБ всего · ~36 МБ свободно
```

Для временных файлов автоматически выбирается подходящее хранилище с учётом свободного места и `MemAvailable`.

В режиме `APK + Compressed` файлы обрабатываются последовательно:

```text
скачать APK
      ↓
установить APK
      ↓
удалить временный APK
      ↓
скачать compressed.tar.gz
      ↓
извлечь sing-box
      ↓
удалить архив
      ↓
заменить /usr/bin/sing-box
```

Это уменьшает пиковый расход `/tmp`, который на OpenWrt обычно находится в RAM.

## ⚠️ Почему нет rollback

На роутерах с небольшим объёмом RAM и flash создание резервной копии большого `sing-box` само по себе может привести к нехватке ресурсов.

Поэтому установщик придерживается принципа **проверить как можно больше до записи** и не создаёт `.bak`, `.old` или другие копии бинарника.

Для режима `APK + Compressed` обычный бинарник из установленного APK остаётся рабочей базой до момента успешной проверки compressed-бинарника. Если optional compressed-этап не удаётся скачать, распаковать или запустить, установка продолжается с обычным бинарником из APK.

После фактической необратимой замены бинарника автоматический rollback не выполняется.

## 🚀 Использование

### Однострочная установка через `wget`

```sh
sh <(wget -qO- https://raw.githubusercontent.com/EikeiDev/OpenWRT-sing-box-extended/refs/heads/main/install.sh)
```

### Однострочная установка через `curl`

```sh
sh <(curl -sSL https://raw.githubusercontent.com/EikeiDev/OpenWRT-sing-box-extended/refs/heads/main/install.sh)
```

### Ручной запуск

```sh
wget -O install.sh https://raw.githubusercontent.com/EikeiDev/OpenWRT-sing-box-extended/refs/heads/main/install.sh
chmod +x install.sh
./install.sh
```

Установщик необходимо запускать от имени `root`.

## 🖥 Поддерживаемые архитектуры

| Архитектура системы | Сборка sing-box | Примеры платформ |
|---|---|---|
| `aarch64` | `arm64` | современные ARM64-роутеры, Raspberry Pi 4/5 |
| `armv7*` | `armv7` | 32-битные ARM-устройства |
| `armv6*` | `armv6` | старые ARM-устройства |
| `x86_64` | `amd64` | x86-роутеры, ПК, виртуальные машины |
| `i386` / `i686` | `386` | старые 32-битные x86-системы |
| `mips` | `mips-softfloat` | MIPS big-endian |
| `mipsel` / `mipsle` | `mipsle-softfloat` | MIPS little-endian |
| `mips64` | `mips64` | MIPS64 |
| `mips64el` / `mips64le` | `mips64le` | MIPS64 little-endian |
| `riscv64` | `riscv64` | RISC-V 64-bit |
| `s390x` | `s390x` | IBM Z |

> [!NOTE]
> Для MIPS compressed/UPX автоматически отключается и используется Normal.

## ⚙️ Требования

- права `root`;
- доступ в интернет;
- `curl` или `wget`;
- `tar` для бинарных сборок;
- на OpenWrt — рабочий `opkg` или `apk` для пакетных режимов;
- достаточно свободного места для выбранной сборки.

## 🔐 GitHub API и TLS

Установщик не содержит встроенного GitHub-токена.

В обычной ситуации GitHub API используется анонимно. Если GitHub вернул rate limit или ошибку авторизации, установщик предложит ввести личный токен с отключённым отображением ввода.

Если HTTPS-соединение не удалось, установщик отдельно предложит повторить запрос без проверки TLS-сертификата. Этот режим не включается автоматически.

Для безопасности GitHub-токен не отправляется через соединение с отключённой проверкой TLS.
